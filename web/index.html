When should AI stop and ask?

A trained intervention gate sits between an AI assistant and its tools and decides, for every proposed action, whether to act, ask a clarifying question, request approval or escalate to a human. Try it on 400 workplace tasks, then see how it compares with simpler policies.

How this was built

Workspace. A fictional company with 20 emails, 15 events, 30 files and an 11-rule operating policy, held in SQLite. Tools only change the sandbox.

Dataset. 25 task templates × 4 instantiations = 100 scenario families; each family has four matched variations that change one factor (recipient, ownership, wording, standing instruction…). Labels come from an ordered annotation rubric.

Gate. Multinomial logistic regression on text cues, tf-idf and workspace lookups about the proposed call, wrapped in hard constraints: a confident prediction can never lower a policy floor.

Simulation. Each decision is played against the sandbox and a scripted human. Unauthorised or prohibited calls are logged as failures; human time per interaction is an assumption (clarify 30 s, approve 15 s, escalate 120 s).

Limitations

Labels are provisional. One author applied the rubric; two independent annotators still need to label the blinded sheet before any agreement or validity claim.

The LLM self-assessment baseline (Policy B) has not been run yet; it needs an API key. The keyword heuristic is a cheap stand-in, not an LLM.

The benchmark is synthetic and author-designed. Scores reflect this workspace and policy, not real agents. The gap between the two splits shows how much a family-level split can flatter a model when templates repeat.

The human is scripted. The basic vs. contextual request toggle is the interface for the planned participant study (Experiment B); no human-subjects data is shown.
